# cpu-inference-lab

Measuring, then reducing, what an LLM must load to run on ordinary CPU hardware.

**Status:** Phase 0 — baseline benchmarks. No results yet.

## Why

LLM token generation is memory-bandwidth bound. On a desktop CPU with ~60 GB/s, a 7B model in FP16 tops out near 4 tokens/second no matter what. Three levers change that: read fewer weights (sparsity / MoE), read fewer bits (quantization, down to 1.58-bit), and get more tokens per read (speculative decoding). This repo benchmarks the best open engines for each lever on one consumer machine, then tries to close one specific gap.

## What's here

- `RESEARCH_NOTES.md` — the levers, the engines, the open gaps
